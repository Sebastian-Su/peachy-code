# PeachyPet 精灵图桌宠 Spec

日期：2026-11-09。状态：需求已经和用户谈定，还没有开工。

本文用到的几个词：
- 「精灵图桌宠」：一只桌宠只有一张透明底大图和一个简短的描述文件。图里每一行是一个动作，每一列是动作里的一帧。这是 Codex 宠物包格式，AgentPet、petdex.dev、openpets.dev 都用这种格式。
- 「视频桌宠」：PeachyPet 现有的桌宠。每个状态有一段带透明通道的视频，每两个状态之间还有一段过渡视频。
- 「桌宠库」：桌宠页里列出的所有已安装桌宠，存在本机的一个文件里。
- 「浏览更多」：桌宠页上打开在线桌宠清单的窗口。

## 一、问题：用户卡在哪

用户在这件事上的原话：

1. 「我之前克隆过一个 AgentPet 开源库，也是 agent 桌宠，你看看它的桌宠实现，好像是纹理贴图那种。」
2. 「直接拉 petdex 和 openpets 的清单。」
3. 「本身大家都是开源的，他们也有可能会拉到我的。」
4. 「B 但不要盲目重写，从 agentpet 里面尽可能地复用。」

背景数字（2026-11-09 实测）：
- PeachyPet 自己做一只视频桌宠很贵。Gothic Maid 一共生成了约 22 张图、36 段视频（包括废弃和重做的），装好后占 68 MB。
- 别人做好的精灵图桌宠很多：openpets 有 1336 只，petdex 有 5208 只，每只约 2 MB。现在 PeachyPet 一只都用不了。
- 「浏览更多」里目前只有 PeachyPet 自己资源中心发布的几只。

## 二、应该发生什么

每条末尾标了验证入口：【单测】是仓库现有的测试目标，【真机】是装到本机后由用户看。

### 存储与兼容

- **S1** 精灵图桌宠和视频桌宠存在同一个桌宠库里，用同一种记录。记录里照常生成 4 个状态的节点和边，视频地址留空，另外加一个可选字段，记录精灵图在哪、每个状态用哪几行。→【单测】导入 boba 后读回记录，4 个状态都在，视频地址为空，精灵图信息完整。
- **S2** 每只精灵图桌宠用「来源 + 标识」区分，来源只有三种：petdex、openpets、本地导入。两个网站上有约 378 只同名宠物，它们算不同的宠物，可以都装上，各自标明来源。→【单测】分别装 petdex 和 openpets 的同名宠物，库里有两只，互不覆盖。
- **S3** 同一来源、同一标识的宠物再装一次，会替换旧的，库里不会出现两份。→【单测】在现有「同一个包再装一次会替换」那条测试的基础上，补一个精灵图版本。

### 本地导入

- **S4** 桌宠页「＋」弹窗里有一个「选择精灵图宠物包」按钮，选一个装着描述文件和大图的文件夹，就能导入。导入后宠物出现在桌宠页，来源记为本地导入。→【单测】用本机已有的 boba 导入一次，库里多一只，名字和描述来自它的描述文件；【真机】从「＋」导入 boba。
- **S5** 不需要预先知道网格有几行几列、每格多大，靠透明空隙切出行和帧。AI 画得不整齐的图、某行帧数不满的图都能切。→【单测】沿用 AgentPet 自带的 4 条切图测试；再用 boba 验证切出 9 行，每行帧数依次为 6、8、8、4、5、8、6、6、6，所有帧高度都是 198 像素。

### 浏览在线清单

两份清单的现状：openpets 是分页清单，共 14 页，每只都有缩略图（约 400 KB）。petdex 是一份 1.87 MB 的完整清单，没有缩略图，只有整张精灵图（约 2 MB），清单里有角色、生物、物件三类。

- **S6** 「浏览更多」顶部有三个标签：PeachyPet、OpenPets、Petdex，打开时默认在 PeachyPet。→【真机】打开「浏览更多」，看到三个标签，默认停在 PeachyPet。
- **S7** 每个标签高度固定，列表在标签内部滚动，切换标签时窗口不变高也不变矮。→【真机】三个标签来回切换，窗口高度不变，长列表在内部滚动。
- **S8** 每个标签有自己的搜索框；Petdex 标签另有类型筛选，可选角色、生物、物件。→【单测】用两份清单各截一小段做固定样本，按名字搜索、按类型筛选，结果条数正确；【真机】在 Petdex 标签里搜索并切换类型。
- **S9** OpenPets 的卡片显示它自带的缩略图，只加载屏幕上看得到的那些。→【单测】打开 OpenPets 标签时，只请求清单和可见卡片的缩略图。
- **S10** Petdex 的卡片默认不加载任何图片，只显示名字、作者和类型。用户点「预览」或「下载」时，才下载这一只的精灵图；下载过的卡片改为显示待机动作的第一帧。→【单测】打开 Petdex 标签时只请求清单，不请求任何精灵图；点一只的「预览」，只产生这一只的请求。
- **S11** 点「下载」后走 S4 同一套安装流程。之前预览时下载过的精灵图直接复用，不重新下载。→【单测】先预览再下载，只下载一次。
- **S12** 一个网站连不上或很慢，不影响另外两个标签，那个标签里显示「暂时连不上」和重试按钮，不会一直转圈。→【单测】让一个来源超时，另外两个照常出列表；【真机】断网后打开，三个标签都给出可重试的提示。
- **S13** 清单读过一次后缓存在本机。下次打开先显示缓存，再在后台更新。→【单测】有缓存时，不等网络就能拿到列表。
- **S14** 「已安装」按「来源 + 标识」判断。装了 petdex 的某只宠物，openpets 里同名的那只不会显示成已安装。→【单测】装了 petdex 的 momo 后，openpets 的 momo 显示为未安装。
- **S15** 同人作品照常列出，不加任何提示，也不做「只看原创」的筛选。→【真机】Petdex 标签里能看到影视角色的同人宠物，没有额外提示。

### 播放

- **S16** 启用精灵图桌宠后，它显示在原来桌宠的位置，并跟着 Claude Code 和 Codex 的状态换动作。四个状态对应的行如下：

  | 状态 | 用精灵图的哪一行 |
  |---|---|
  | 待机 | 待机 |
  | 工作 | 奔跑、向右跑、向左跑，三行随机 |
  | 求关注 | 等待 |
  | 思考 | 检查 |

  挥手、跳、失败三行这次不用。→【单测】给定每个状态，取到的是对应的行；【真机】启用 boba，让一个会话开始工作、发起权限请求、结束，看动作是否跟着变。
- **S17** 工作状态每播完一轮，就在奔跑、向右跑、向左跑里重新随机选一行。同一行可以连续被选中。宠物缺哪几行，就只在剩下的行里选；三行都缺时退回待机那一行。→【单测】固定随机种子，连续多轮会选出不同的行；缺行时只从剩下的行里选，全缺时退回待机。
- **S18** 某个状态对应的行缺失时，退回待机那一行，不出现空白。→【单测】只有 1 行的图，4 个状态都播这一行。
- **S19** 切换状态时，等当前这一轮播完再切，没有淡入淡出，新动作从第一帧开始播。→【单测】在现有「状态切换等到循环边界」那组测试里补精灵图用例。
- **S20** 帧率按动作区分：工作每秒 8 帧，求关注每秒 4 帧，待机和思考每秒 3 帧。→【单测】每个状态拿到的帧率正确；【真机】肉眼看待机比工作慢。
- **S21** 摆放：底部居中，坐标取整到整像素；一只宠物的 4 个状态统一用一个缩放比例，按所有帧里最宽、最高的那一帧算，切换状态时宠物不会忽大忽小。缩放按窗口铺满，不取整数倍：原来照搬 AgentPet 取整数倍，petdex、openpets 的帧高约 198–203 像素，默认 150 点窗口（Retina 下 300 像素）只能放 1 倍，宠物只占窗口高度约三分之二，用户反馈「渲染都很小」（2026-11-10）。缩放恰好是整数倍时用最近邻放大保持像素清楚，否则平滑边缘，避免插画风的软边出现锯齿。→【单测】一组宽度不同的帧缩放比例相同且铺满画布高度；203 像素高的帧在 300 像素画布里高 300；整数倍才判定为最近邻；【真机】默认尺寸下宠物铺满窗口高度，切换状态时大小不跳。
- **S22** 桌宠页卡片和侧栏底部显示精灵图桌宠的静态形象，用待机动作的第一帧。→【真机】在桌宠页和侧栏看到 boba 的形象。

### 删除与缓存

- **S23** 删除一只精灵图桌宠时，连同它安装的文件一起删掉。→【单测】删除后，这只宠物的安装目录不存在了。
- **S24** 只预览过、没安装的精灵图存进本地缓存，缓存总量上限 200 MB，超了就先删最久没用过的。→【单测】缓存写满后再存一张，最久没用的那张被删掉，总量不超过上限。
- **S25** 视频桌宠的播放和删除行为不变。→【单测】现有全部测试照常通过（当前 428 个，0 失败）。

### 发布到资源中心

- **S27** 本地导入的精灵图桌宠可以用现有的发布流程打成资源中心的包：包里带上精灵图和待机首帧，描述文件里的图片地址改成包内的相对路径。→【单测】用一个本地导入的宠物跑一遍发布流程，再用资源中心的安装流程装回来，4 个状态的行、图片都在，能正常播放。
- **S28** 从资源中心装回来的精灵图桌宠，删除时不会误删同标识的本地导入宠物的文件。→【单测】本地导入一只 boba，再从资源中心装一只同标识的 boba，删除后者，前者的文件夹还在。

### 复用

- **S26** 切图、逐帧播放、拉清单这三部分尽量复用 AgentPet 的代码（MIT 许可），保留它的版权声明；单只宠物的下载和安装沿用 PeachyPet 现有的安装流程，不照搬 AgentPet 的。→【真机】代码审查时确认复用的部分带有 AgentPet 的版权声明。

## 三、绝对不能发生什么

- **N1 不能弄丢已有的桌宠库。** 现在桌宠库文件只要有一条记录读不出来，应用就把整个库当成空的，下次保存时整份覆盖。精灵图桌宠是新加的记录，如果用户回退到旧版本 PeachyPet，旧版本读不懂它，就会把整个库清空，Gothic Maid 这种花钱生成、没法原样重来的桌宠也会一起丢掉。这种事做错了撤不回来。→【单测】把一个含精灵图桌宠的库文件交给只认视频桌宠的旧解码方式，视频桌宠都能读出来，整份不会读失败。
- **N2 不能改动或删除用户的视频桌宠文件。** 包括导入失败、导入到一半被取消、删除精灵图桌宠这些情况。→【单测】导入失败后，以及删除一只精灵图桌宠后，视频桌宠目录的文件清单和之前完全一致。
- **N3 不能替用户批量下载，也不能再分发别人的作品。** 只下载用户点过的那一只。不在 PeachyPet 自己的服务器或资源中心镜像、转存、重新发布这些宠物；发布流程遇到来源是 OpenPets 或 Petdex 的宠物直接拒绝。一旦再分发，作品就脱离了原网站的下架机制，收不回来。→【单测】浏览、预览、下载的整个过程中，除了用户点过的那一只，不产生其他精灵图请求；对来源是 OpenPets、Petdex 的宠物跑发布流程，失败退出，不生成包。
- **N4 导入的包不能往包外写文件。** 描述文件里的图片路径如果指向包外（比如用上级目录跳出去），就拒绝导入，并且不留下任何文件。→【单测】在现有「媒体路径跳出包外被拒绝」那条测试的基础上，补一个精灵图版本。
- **N5 一只坏宠物不能弄崩应用，也不能卡住桌宠层。** 图片解不开、切出来是 0 帧、清单里有一条格式错了，都只能让这一只导入失败，或者这一条不显示。→【单测】空图、全透明图、清单里混入一条坏记录，各验一次。

## 四、待定

用户在这件事上没有说过「待定」，所以这一节没有用户的待定条目。

下面这件事在盘问中没有谈到，我也没有替用户决定：

1. ~~精灵图桌宠能不能发布到 PeachyPet 自己的资源中心~~ 用户已定（2026-11-09）：能发布，只限本地导入的；从两个网站下载的不能发布（见 S27、S28、N3）。

## 五、这次不做什么

- 不做拖拽导入。
- 不做淡入淡出等过渡效果。
- 挥手、跳、失败三行不接入任何状态，也不为它们新增「完成」「失败」这类状态。
- 不做宠物在桌面上走来走去；向左跑、向右跑只是原地朝那个方向跑。
- 不做视频桌宠和精灵图之间的互相转换。
- 不做精灵图的生成工具，也不改现有的视频桌宠生成 skill。
- 不搭自己的中转服务器，也不镜像、转存第三方清单和素材。
- 不在浏览页给同人作品加提示，不做「只看原创」筛选。
- 不事先联系 petdex 和 openpets 征求许可。
- 视频桌宠删除时是否连文件一起删，这次不改。
- 不做 AgentPet 的养成玩法，比如经验值、升级、成就。
- Windows 和 Linux 不在范围内。

## 六、从哪儿验

只用两个入口，优先用第一个：

1. **【单测】仓库现有的测试目标。** 宠物包安装测试、覆盖层状态机测试，加上全量测试。存储兼容、切图、导入、路径安全、清单解码和搜索、请求次数、缓存、状态对应、切换时机、缩放都在这里验。素材用本机已有的 boba，清单用截下来的小段固定样本，测试本身不联网。
2. **【真机】用户在本机看。** 用正式签名脚本安装后，由用户确认：三个标签的布局、断网提示、boba 的显示和动作跟随、像素是否清楚、静态形象。这台机器的终端没有屏幕录制权限，所以这一步只能由用户来看。
