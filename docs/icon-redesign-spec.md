# [PeachyPet] 应用与状态栏图标规格（2026-11-12）

本规格记录最终确认的应用 B「屏幕猫」和顶部状态栏 02「屏幕猫」。它们取代此前的 02「简化符号」；旧稿保留为历史，不能混淆两次编号。对象是 PeachyPet macOS 桌宠应用。

用户已授权全部切换、编译、正式签名、覆盖安装和验证；验证通过后直接合入主分支并 push。该授权不包含创建 Release、发布安装包或覆盖无关工作。

## 问题

用户在实际使用中遇到的问题是：

- “一般的 icon 都是完整内容包裹，所以这个对话框被头像压住了。”
- “这个头像有点不可爱，太单调，太粗糙。”
- “小猫改成偏中性化一点的，不要这么明确地表现出是个小女猫，只是看上去非常调皮可爱。”
- “这个小猫又有点过于精细了，不适合当下扁平 UI 时代的风格吧。”
- “状态栏需要单独用这种单色的 icon，原来状态栏的 icon 看着还行，就是有点单薄不像其他的那样铺满。”
- “突然感觉这个 icon 很廉价啊，尤其放在 dock 里一看。”
- “这些版本又看不出来是 Agent pet 相关的了。”

用户希望应用图标既有小猫的亲近和调皮，又能认出 Agent 的指令特征；放在 Dock 中要显得简洁、完整。顶部状态栏要用同源单色形状，轮廓饱满，缩小后仍清楚。

## 应该发生什么

应用以用户在 Dock 比较后选定的 B 为准；状态栏以随后选定的 02 为准。只提取、去除展示背景及缩放，不用生成式工具重新解释选定造型。

## 绝对不能发生什么

- 不删除或覆盖确认原图、历史候选、旧资源和可恢复的旧安装版；不以清理为由重画确认角色。
- 不把用户实际使用的桌宠改成品牌猫，不覆盖宠物素材、创作项目、会话或设置；测试不能向真实用户数据灌入样例。
- 不混入旧的精细小猫、旧 02「简化符号」或早期 C3；不把彩色应用图或带底色的预览充当状态栏模板。
- 不改工作、空闲、未读及提醒的业务判断。仍由现有工作会话条件选择图形，未读通知用红点；不新增提醒状态触发。
- 不把文件导出、单元测试通过或合成预览说成安装验收通过；真实窗口、系统入口与原生状态必须有对应版本证据。
- 不使用临时签名替代原正式身份，不因测试擅自改变其他应用权限；若需临时权限，遵守已授权范围及撤销要求。
- 不把用户原有未提交改动混入提交，不强推、不改写主分支历史，不创建 Release 或发布安装包。

## 待定

**无。** 用户没有明确说“待定”的条目。应用 B、状态栏 02、编译签名安装、验证后合入主分支和 push 均已确认。

实现中发现无法确认的选择须单独记录并说明应由项目负责人（用户）裁决，不能把实现者的推测写成用户已决定。

## 这次不做什么

- 不再探索新造型、不重画字标、不更名、不改 UI 皮肤、导航或布局。
- 不替换 Agent／宿主应用图标、系统功能符号、宠物海报或实际动态桌宠。
- 不新增动画图标、会话或通知功能，不变更权限路由。
- 不改说明正文、网站或其他传播渠道；仅更新现有共用图标素材。
- 不发布 Release 或安装包，不吸收与图标无关的工作。

## 从哪儿验

按入口从高到低检查，复用现有能力，不另建一套测试系统。

1. **真实原生入口。** 同一待验版本的 Finder、Dock、顶部菜单栏、主窗口与菜单栏弹窗；首次引导在隔离实例中使用同一生产视图与资源。工作、空闲、未读及已读回落经现有事件入口触发，在系统深浅外观检查，不修改真实用户数据。
2. **选定稿与原尺寸对照。** 比较应用 B、状态栏 02、导出尺寸、透明边缘和单色反白。合成预览仅用于造型，不作为安装证据。
3. **现有图标专项测试、应用包校验与 Git。** 先给新确认稿身份补失败证据，再替换资源使整个测试文件通过；核对模板、分辨率、品牌共用、签名及安装一致。最后核对保护快照、提交范围、主分支与远端。

验收终点是全部入口显示选定稿、原状态行为保持、正式签名安装版有真实界面证据、原有工作受保护，并且对应提交已合入主分支及推送成功。
