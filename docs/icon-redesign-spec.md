# [PeachyPet] 应用与状态栏图标规格（2026-11-11）

本规格记录已经谈定的设计与验收要求。对象是 PeachyPet macOS 桌宠应用；最终选择为 **02「简化符号」**，此前方案仅作探索历史。

当前已完成设计资产交付和使用位置盘点，尚未替换应用资源，也未验收安装后的真实效果。本轮只整理规格，不启动接入或发布；规格不绑定开发分支。

## 问题

用户卡在图标的造型、细节和实际显示效果上：

- “一般的 icon 都是完整内容包裹，所以这个对话框被头像压住了。”
- “这个头像有点不可爱，太单调，太粗糙。”
- “小猫改成偏中性化一点的，不要这么明确地表现出是个小女猫，只是看上去非常调皮可爱。”
- “这个小猫又有点过于精细了，不适合当下扁平 UI 时代的风格吧。”
- “状态栏需要单独用这种单色的 icon，原来状态栏的 icon 看着还行，就是有点单薄不像其他的那样铺满。”

用户希望应用图标有漂亮、调皮的小猫，也能让人联想到 Agent 陪伴；缩小后仍清楚。状态栏则保留原图案，让它看起来更饱满。

## 应该发生什么

以用户最后选择的 02 原图及配套加粗状态栏模板为视觉基准。以下验法是后续执行办法，不代表本轮已经通过。

|---|---|---|

| A3 | 边框沿用最终 02 中偏狐狸橙红的颜色，保留奶油底色；原先指定的 #FF5500 不被解释为整张图必须统一用这一色值。 | 对照最终 02 配色检查导出图；只允许缩放产生的边缘差异，不另选橙色或改动全局界面主题。 |

## 绝对不能发生什么

- 不覆盖或删除选定的 02 原图、历史候选和原有资源，使确认结果无法找回；不以生成式清理为由悄悄重画已选角色。
- 不把用户实际使用的桌宠替换成品牌小猫，不覆盖宠物素材、创作项目、会话或设置。品牌图标变更不应造成用户数据损失。
- 不混入旧的精细小猫或早期 C3 图案，不用彩色应用图直接充当状态栏图。
- 不把素材中的“提醒”状态接成新的通知逻辑。当前有工作会话时显示工作图，否则显示空闲图；未读通知仍用红点，不能因改图改变含义。
- 不把“文件已导出”“测试通过”说成“安装后已经验收”；也不能仅更新说明文档中的图片就声称 Dock 或状态栏已更新。
- 本轮不替换已安装应用、不发布、不推送代码；不得把本规格视为这些操作的授权。

## 这次不做什么

- 不重新探索概念，不更名，不重做字标、UI 皮肤或全局配色。
- 不改 Agent／宿主应用图标、导航和按钮符号、宠物海报或动态桌宠素材。
- 不要求把彩色主图重新绘成纯矢量，也不新增动画图标。
- 不新增提醒状态触发逻辑，不改会话、通知或权限交互。
- 不执行应用资源接入、安装或发布；不把透明窗口品牌图、README、网站等渠道同步自动纳入本轮。

## 从哪儿验

按入口从高到低检查，复用现有能力，不另建一套测试系统。

1. **接入后的真实应用。** 在同一待验版本查看 Finder／Dock 和系统菜单栏，触发空闲、工作、未读通知，检查实际尺寸、深浅背景与原有状态行为。若另行确认窗口品牌图接入，再覆盖主窗口、首次引导和菜单栏弹窗三处；不要把这些入口默认为已验。
2. **现有图标对照展示。** 直接使用选定的 02 预览、原尺寸阶梯和状态栏前后对照，验 A1—A5、A7。它能判定设计与导出是否一致，不能证明安装包已经生效。
3. **现有图标专项测试与应用包资源校验。** 用图标测试检查三态、18／36 像素表示、18 点显示尺寸、透明角与模板属性；应用包校验检查资源能随包读取。现有测试把可见像素限定为白色，新素材为黑色模板，接入时应验证单色模板契约，不能把固定白色当作用户需求，也不能直接删掉透明度或尺寸检查。

当前结论是“设计已确认、资产已交付、应用尚未接入”。后续接入完成的验收终点是：同一待验版本通过资源检查，并在真实 Dock／菜单栏显示选定图形且保持现有行为；导出包或测试单独通过均不能替代这个终点。
