# PeachyPet 服务控制台 Spec

日期：2026-11-05。状态：需求已经和用户谈定，还没有开工。

本文中的「服务页」指主窗口侧栏里新增的「服务」入口。「注册服务」指用户或 Agent 按约定格式登记给 PeachyPet 的启动命令。「系统服务」指 brew services 和 LaunchAgent / LaunchDaemon。

## 一、问题：用户卡在哪

用户的原话：

1. 「我电脑上装了各种什么 Ollama，各种 brew service、ComfyUI、系统服务以及其他各种自动启动或者需要手动启动的服务或和 Web，但是很散乱。」
2. 有些东西每次都要手动敲命令或者跑脚本，比如 ComfyUI、git-pull-all 这类常用脚本。用户说：「ComfyUI 和 Ollama 我一般都是命令行启动或者直接用 CC 替我启动」。
3. 「我下载了一个什么开源框架，但是启动需要脚本或者 npm 命令，我用 AI 说注册到 PeachyPet，就能自动注册进去。」
4. 用户希望在一个地方看到这些东西：在不在跑、点一下能启动、停止或重启，能直接打开对应的网页；脚本失效了要能看出来，并建议删掉。

用户明确说过：不需要自动扫描依赖，也不需要默认扫描整个磁盘上的脚本。

扫描用户这台机器得到的现状：brew 服务有 4 个，用户自己的 LaunchAgent 有 hermes ×2、paseo、mihomo，系统 daemon 里有 1 个是用户自己的（utm-clash-bypass），AI 工具目录下有 204 个项目。这些服务平时散落在终端、launchctl 和 brew 里，没有统一的入口。

## 二、应该发生什么

每条末尾标了验证入口，三种入口的定义见第六节：【单测】【真机】【Agent】。

### 注册

- **S1** 服务页有一个固定的注册目录，每个服务对应一个文件，文件名就是这个服务的标识。标识只能用小写字母、数字和连字符。→【单测】合法和不合法的文件名各验一组。
- **S2** 注册文件必须有这几个字段：格式版本（目前是 1）、显示名、类型（`service` 表示常驻服务，`task` 表示跑完就退出的任务）、启动命令。可选字段有：工作目录（支持主目录简写）、打开地址、端口、环境变量、一句说明。→【单测】必填字段都齐、缺一项、类型非法，三种情况都要验。
- **S3** 有一个文件格式错了（解析失败、缺必填字段、格式版本不认识），只有这一条显示「格式错误」和原因，并提供删除按钮，其他条目照常显示。→【单测】目录里同时放好文件和坏文件，好的照常读出来。
- **S4** 文件里有不认识的字段，直接忽略，不算错误。→【单测】
- **S5** 注册目录里新增、修改或删除文件后，服务页在 1 秒内更新，不用重启 PeachyPet。→【真机】服务页开着时新增一个文件，再删掉，看页面变化。
- **S6** 一份格式说明和一份 JSON Schema 放在仓库里，它们是格式的唯一来源；最小 skill 引用它们，不另抄一份。→【单测】用 Schema 校验第 S2 条那组样例，结果要和应用的解析结果一致。

### 启动、停止与状态

- **S7** 点「启动」后，命令通过用户的登录 shell 执行，conda、fnm、brew 的 PATH 都能生效，效果和在终端里敲这条命令一样。→【真机】注册一个依赖 brew 路径的命令（例如启动 Ollama），从服务页启动成功。
- **S8** 注册服务交给系统的后台任务机制托管，PeachyPet 退出、升级或重启时，这些服务继续运行。→【真机】启动一个服务后用正式打包脚本重装 PeachyPet，服务进程还在，端口还在监听。
- **S9** 这种托管只在当前这次运行有效，不会开机自启。点「停止」后，托管任务会被清理干净。→【真机】停止后，系统的后台任务列表里找不到这条 PeachyPet 任务。
- **S10** 填了端口的服务，只要端口在监听，就显示「运行中」，不管是谁启动的。在 PeachyPet 之外启动的（终端里或让 CC 启动的），会标明「外部启动」。→【单测】用固定的进程和端口数据推导状态；【真机】在终端里启动 Ollama，服务页显示「运行中（外部启动）」。
- **S11** 端口在监听，但占用它的进程和注册信息对不上（工作目录和命令都不匹配），就显示「端口被其他程序占用」，不提供停止按钮。→【单测】
- **S12** 停止「外部启动」的服务前，每次都弹窗确认，弹窗里写明要结束的进程号和完整命令行。确认后先正常结束进程，10 秒后还没退出才强制结束。→【单测】结束顺序；【真机】停止一次在终端里启动的服务。
- **S13** 「重启」外部启动的服务时，先按 S12 停掉它，再由 PeachyPet 启动；重启之后这个服务归 PeachyPet 管。→【真机】
- **S14** 填了打开地址的服务，可以点按钮在浏览器里打开。→【真机】
- **S15** `task` 类型运行期间，「执行」按钮不能点，不会重复执行。结束后显示退出码、耗时和最后几行输出。→【单测】状态流转；【真机】执行一次 git-pull-all。
- **S16** 每个注册服务都有自己的日志，在服务页能直接看到，每个服务的日志最多保留 5 MB。PeachyPet 重启以后，之前的日志还在。→【真机】
- **S17** 状态只在服务页打开时刷新，每 3 秒一次；brew 服务的状态每 10 秒查一次。服务页关着的时候，不在后台轮询。→【真机】服务页关闭后，观察一段时间内 PeachyPet 没有发起状态查询。

### 第一次运行前确认

- **S18** 新注册的命令，以及改过的命令（启动命令、工作目录、环境变量任意一项变了），第一次运行前都要弹窗，显示完整的命令、工作目录、环境变量，以及文件的修改时间。用户确认后才执行。→【单测】指纹的计算和比对；【真机】注册一条新命令，第一次点启动时出现弹窗。
- **S19** 确认过的指纹存在 PeachyPet 自己的数据里，不写回注册文件。之后启动、重启都不再弹窗。→【单测】
- **S20** 注册文件被改过、指纹对不上时，按钮变成「确认并启动」，并标出变了的是哪一项。只改显示名、打开地址、说明，不需要重新确认。→【单测】每个字段各改一次，验证需不需要重新确认。

### 有效性与删除

- **S21** 有效性只检查三件事：工作目录存在；命令里第一个可执行文件能找到；文件能解析。任何一项不通过，就标「已失效」，说明原因，并给出删除建议。依赖不检查，磁盘也不扫描。→【单测】三种失效各验一次。
- **S22** 删除注册服务时，把文件移到废纸篓，能找回来。服务还在运行时，先提示用户把它停掉。→【单测】删除后文件在废纸篓里；【真机】

### 系统服务

- **S23** brew 服务全部显示，提供启动、停止、重启。→【真机】用户机器上的 4 个 brew 服务都出现在服务页。
- **S24** 用户自己的 LaunchAgent（指向的程序在用户主目录或 Homebrew 目录下）显示出来，并且可以操作。和 brew 服务重复的只显示一条。→【单测】用 hermes、paseo、mihomo、Google 更新这几份样例做分类；【真机】页面上出现 hermes ×2 和 paseo，mihomo 只出现一次。
- **S25** 应用自带的 LaunchAgent 默认隐藏，展开后可以看，但只读。→【真机】
- **S26** 系统 daemon 只显示用户自己的 utm-clash-bypass，只读，并给出一条可以复制的 sudo 命令，用户自己到终端里执行。→【真机】
- **S27** 系统服务的「停止 / 启动 / 重启」只影响这一次运行，不改变开机自启。设了 KeepAlive 的服务点停止后，确实停下来，不会马上被拉起。→【真机】停止 hermes，过 30 秒后确认它没有被重新拉起，再启动恢复。
- **S28** 「开机自启」是单独的开关，关掉之前要确认。改了它，只影响下次开机。→【真机】把 mihomo 的开机自启关掉，再打开，检查注册状态变化，最后恢复原样。

### Agent 注册

- **S29** 用户对 Agent 说「把 XX 注册到 PeachyPet」，Agent 按 skill 写出一个合法的注册文件，并且只注册、不启动。→【Agent】用一个真实的 Agent 注册 ComfyUI，生成的文件通过 Schema 校验，PeachyPet 里出现这个条目，状态是「待确认」，不在运行。
- **S30** skill 只有一份，放在用户级 skill 的真实目录里，再按全局规则软链接给 Claude 和 Codex。→【Agent】从两个 Agent 的入口都能读到同一份 skill。

### 外观

- **S31** 服务页使用当前皮肤；中英文切换后，新增的文字都有翻译。→【单测】复用现有的翻译键覆盖测试；【真机】

## 三、绝对不能发生什么

前四条做错了，后果撤不回来。

- **X1 命令被调包后静默执行。** 注册文件里的命令变了，却没经过用户确认就执行了。→【单测】
- **X2 误杀无关进程。** 只要进程和注册信息对不上，就不能停它；对得上的外部进程，也必须确认之后才能停。→【单测】
- **X3 PeachyPet 自己执行 sudo 或申请管理员权限。** 系统 daemon 只读，操作只能由用户复制命令自己执行。→【单测】代码审查加测试：系统 daemon 的条目上没有任何操作入口。
- **X4 悄悄改掉开机行为。** 只有点「开机自启」开关并确认之后，开机自启才会变，点「停止」不能顺带把它改掉。这一版也不往用户的 LaunchAgents 目录写任何文件。→【真机】操作前后对比 LaunchAgents 目录。
- **X5 打开页面或注册服务时自动执行命令。** 只有用户点按钮才执行。→【单测】
- **X6 新开 HTTP 注册接口。** 本地服务目前没有鉴权，开了这个接口，等于任何本机程序和网页都能让 PeachyPet 执行命令。→ 代码审查：本地服务的路由不增加。
- **X7 PeachyPet 退出时把正在运行的服务一起带走**，或者停止之后留下没清理的托管任务。→【真机】
- **X8 注册文件里的凭据写进日志或通知。** 环境变量里如果有 Token，日志、通知、确认弹窗以外的界面都不能显示。保存前统一做凭据替换。→【单测】
- **X9 一个坏的注册文件让整个服务页打不开**，或者让 PeachyPet 启动失败。→【单测】

## 四、待定

这轮盘问里，用户没有说过「待定」。下面这些是我直接定下来的细节，用户没有表示反对，记在这里，方便以后翻查：

- 服务页放在侧栏「代理」和「桌宠」之间，页面分成三组：已注册、brew、LaunchAgent。
- 删除就是移到废纸篓。
- 日志上限 5 MB。
- 状态刷新间隔 3 秒，brew 服务 10 秒。

## 五、这次不做什么

- 注册服务的开机自启：不做，也不往 LaunchAgents 目录写文件。
- 自动扫描磁盘、发现候选项目。
- 检查依赖，比如 node_modules、Python 虚拟环境、Docker 有没有在跑。
- 帮用户在服务页里编辑注册文件。改的话，用编辑器打开，或者让 Agent 去改。
- 命令行注册工具，以及 HTTP 注册接口。
- 申请管理员权限去操作系统 daemon。
- 操作应用自带的 LaunchAgent。
- PeachyPet 自己的 Agent 能力。以后有了，复用同一份注册格式和 skill 就行。
- Docker 容器管理。

## 六、从哪儿验

只用三个入口，按从上到下的顺序：

| 标记 | 入口 | 负责什么 |
|---|---|---|
| 【真机】 | 用正式打包脚本装好的 PeachyPet，在用户这台机器上，按第二节逐条走一遍。被操作的服务（Ollama、hermes、mihomo）操作完要恢复到原来的状态 | 这个入口覆盖面最大：launchd 托管、外部进程识别、系统服务的启停和开机自启，都只能在真机上验 |
| 【Agent】 | 用真实的 Claude Code 或 Codex，让它注册一个服务 | skill 能不能用、Agent 是不是只注册不启动 |
| 【单测】 | 现有的 Swift 单元测试，测试运行时和真实用户数据是隔离的 | 格式解析、状态推导、指纹确认、进程匹配、坏文件隔离这些没法在真机上穷举的部分。新用例都加在这里，不另开入口 |
